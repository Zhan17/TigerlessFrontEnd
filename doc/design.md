## Hero audit

Hero 容易暴露字体、行宽、换行、图片比例和中间宽度布局问题，因此优先核对；它不替代全页验收。

| 项目 | 已知或候选 | 下一次需要的证据 |
| --- | --- | --- |
| 内容 | 笔记提到徽章、标题、CTA、语言胶囊、分类卡 | 两个画板的 Hero 节点与局部截图 |
| 标题 | 笔记提到 “speaks your language” 高亮 | 准确文本、字体/字重、字号、行高、实际换行 |
| 布局 | 不能仅凭描述决定 flex/grid 或绝对定位 | 容器宽度、留白、元素顺序、卡片尺寸及移动变化 |
| 语言胶囊 | 笔记提到两行、边缘淡出及混合书写方向 | 实际列表、RTL 内容；是否有明确运动规格 |
| 响应式 | 375 / 1440 忠实，320–1920 完整 | 最小宽度、布局切换条件、断点附近截图 |
| 交互 | PDF 要求状态和过渡，未提供 hover 设计 | CTA/card 的真实操作；最终状态和 Storybook 覆盖 |

Hero layout 的最终方案和 rejected alternatives 写入 [decisions.md](decisions.md)，本文件只保存观察、证据与待验证问题。

## 设计问题的处理

先核对原稿，再判断是否需要偏离；修正设计错误不意味着可以任意改版。

| 候选问题（来自笔记） | 需核对什么 | 当前状态 |
| --- | --- | --- |
| `Issuance` / `Comapny` 等拼写 | 原稿确实存在且上下文支持修正 | 未核实、未修复 |
| BMI 输入与结果不一致、区间文案异常 | 实际默认值、结果含义、产品预期 | 未核实、未修复 |
| 移动画板缺少减重内容 | 是否在独立画板，最终页面顺序如何 | 未核实、未修复 |
| 产品图与品类不符 | 原始素材、可用替代素材与展示意图 | 未核实、未修复 |
| 语言胶囊挤压或不同方向内容混排 | 字符串、容器、语言方向 | 未核实、未修复 |

不从人名推断人物性别或身份，也不把所有刻意的局部裁切都当成设计错误。疑问保存为疑问，避免为了增加 deviation 数量而改设计。

一旦实施修正，直接把“原问题 → 改动 → 原因 → 验证”写入根 [README](../README.md) 的 Design deviations。自设计交互也直接记录在 README；不另建重复偏差日志。

## Tokens、素材和状态

- Tokens 按实际需要采集：颜色、字体/字重、字号/行高、间距、圆角、容器宽度、过渡时长。数值未读取前不猜测为“已确认”。
- 素材记录实际文件与用途，说明必要的替换；图片比例、裁切和 alt 按真实内容决定。
- 对每个实际可交互组件列状态，再安排 stories；不要给无交互的静态区块人为增加状态。
- 若实现菜单、手风琴、计算器或轮播，补充键盘操作、开关/输入/结果状态与边界；具体集合依据最终设计确定。
- 动画是否存在于设计、是否为自行设计需分清；静态胶囊并不自动要求无限滚动。
